# Pibox

Pibox is a Pi extension that creates complete Pi RPC workers in Microsandbox or smolVM sandboxes. Sandbox configuration stays provider-native; Pibox owns only worker naming, bootstrap, RPC, authentication, and cleanup.

## Requirements

- Node.js 23.6.0 or newer
- one supported sandbox runtime:
  - Microsandbox 0.7.14 (installed with this package; Pibox selects its matching bundled runtime rather than a stale runtime in `~/.microsandbox`);
  - smolmachines 1.6.6 plus a compatible `smolvm` CLI for duplex processes
- at least one model credential in the host Pi profile

```sh
npm install
npm run typecheck
npm run lint
```

## Quick start

Install dependencies, choose a provider example, and start Pi with the Pibox extension:

```sh
npm install
(cd examples/microsandbox && pi -e ../../src/index.ts --pibox)
```

`--pibox` reads `pibox.toml` from the current directory, creates the configured worker, and routes normal prompts and user bash commands to it. Remove the worker with `/pibox-rm`.

Alternatively, start Pi without creating a worker and use the commands interactively:

```sh
pi -e ./src/index.ts
```

```text
/pibox --config examples/microsandbox/pibox.toml
/pibox-rm <worker-name-shown-at-startup>
```

For repeated local use, `pi install .` loads the package without `-e`, so `pi --pibox` is sufficient. A Docker Compose example with TanStack Start, Quarkus, PostgreSQL, mise, and a bind-mounted Microsandbox workspace is available in [`examples/microsandbox/full-stack/`](examples/microsandbox/full-stack/).

## Configuration

Pibox loads `pibox.toml` from the current directory unless a command or tool supplies another path.

```toml
provider = "microsandbox"

[pibox]
name = "pibox-demo"
nameSuffix = "worktree"
workdir = "/workspace"

[sandbox]
image = "ghcr.io/manuschillerdev/pibox-base:bookworm"
ephemeral = true
replace = true
```

`provider` must be `microsandbox` or `smolvm`. `[pibox]` controls the worker name and guest working directory. `[sandbox]` is passed unchanged to the selected adapter and uses that provider's native names, units, and structures.

### Caches

Pibox can mount disposable package-manager caches and apply each tool's documented cache environment automatically:

```toml
[caches.pnpm]
scope = "repository"

[caches.maven]
scope = "user"

[caches.mise]
scope = "user"
```

`repository` is the default scope and is shared by Git worktrees through their common Git directory. `user` shares the cache between all Pibox workers owned by the current host user. A known preset's guest mount can be overridden without separately changing its environment:

```toml
[caches.pnpm]
mount = "/custom/pnpm-cache"
```

Built-in presets are `npm`, `pnpm`, `yarn`, `bun`, `pip`, `uv`, `poetry`, `maven`, `gradle`, `cargo`, `go`, `nuget`, `composer`, `bundler`, `deno`, and `mise`. Unknown cache names require an explicit absolute `mount` and do not generate environment variables.

Host data lives under `$TMPDIR/pibox-<uid>/caches/user/` or `$TMPDIR/pibox-<uid>/caches/repository/<repository-hash>/`. Cache data is disposable and may be removed by the host operating system. `[pibox.env]` may contain additional literal environment values; names generated by cache presets cannot be overridden there.

Pibox uses its Debian base image, which includes the pinned Node.js and Pi runtime under `/opt/pibox`, mise, Docker Engine, its matching CLI, and Docker Compose. Docker uses the nested-VM-compatible `vfs` storage driver. Pibox starts Docker, runs `mise install` in the configured workdir, writes the guest extension and auth file through stdin, and starts Pi in RPC mode. See [`examples/`](examples/) for each provider.

## Images

Pibox publishes one multi-architecture Debian OCI image for Microsandbox and smolVM. Build and publishing commands are in [`images/README.md`](images/README.md).

## Start and communicate

Start Pi with the configured worker already selected:

```sh
PI_CODING_AGENT_DIR="$HOME/.pi/profiles/pibox-controller" pi --pibox
```

Interactive commands:

- `/pibox` creates or enters the worker for the current worktree. Repeating it reconnects to that active worker without replacing its session.
- `/pibox-leave` disconnects and stops the routed worker.
- `/pibox-leave --keep-running` disconnects without stopping it.
- `/pibox-stop [worker]` stops an active worker.
- `/pibox-rm [worker]` stops and removes an active worker.

Model-facing tools retain their worker names: `worker_create`, `worker_prompt`, `worker_state`, `worker_steer`, `worker_abort`, `worker_set_model`, and `worker_remove`.

## Authentication

Credential discovery remains in the worker layer. Provider adapters install credentials according to their native security model:

- **Microsandbox:** TLS secret substitution with live rotation.
- **smolVM:** blocked by default because the real token enters the guest process environment. To explicitly accept that weaker policy, set `PIBOX_SMOLVM_AUTH_POLICY=guest-environment`. Pibox then passes host environment references through `smolvm machine exec --secret-env`; it does not write the token to the guest auth file.

The local smolmachines SDK does not apply `MachineConfig.image` to the persistent guest rootfs. The smolVM adapter therefore uses the CLI consistently with the opaque `[sandbox]` table serialized as a Smolfile, preserving a Debian image-backed machine for creation, lifecycle, and raw duplex execution. Do not add `-t`; Pi RPC requires unmodified pipes.

See [`docs/typescript-extension-auth-relay.md`](docs/typescript-extension-auth-relay.md) for the architecture and verification matrix.
